# Balmi Safety

- 상태: **제품 방향 명세** (docs-first). 실제 119 자동 연결·워치 HR 추론·CGM 진단은 **구현하지 않음**.
- 관련: [`SPEC.md`](SPEC.md) · [`개발노트.md`](개발노트.md) · Activity Recovery(회복 체크, PR `#7` / `cursor/activity-recovery-36aa`)

---

## 한 줄

**Recovery**는 운동 후 음식·물·휴식 안내. **Safety**는 그 위(또는 옆)에서 이상 신호 → 사용자 확인 → 보호자/긴급 대응을 담당한다.

Safety는 의료기기·진단이 아니다. 워치 심박·떨림·모션만으로 **저혈당을 진단하지 않는다.**

---

## Recovery vs Safety

| 모듈 | 역할 | 소유 |
|------|------|------|
| **Activity Recovery** | 음식, 물, 휴식, 회복 프로토콜 | 증상·섭취·재확인 안내 |
| **Balmi Safety** | 이상 감지 → 사용자 확인 → 보호자 → SOS | 이상 신호·확인·긴급 대응 |

**교차 규칙**

- Recovery가 사용자 입력 증상(떨림/어지러움 등)을 **신호로 제공**할 수 있다.
- Safety가 **SOS / 긴급 에스컬레이션**을 소유한다. Recovery는 `저혈당인가요? → 119` 직행 UX를 갖지 않는다.
- Recovery MVP가 별도 PR인 동안 본 문서는 계약만 고정한다. 병합 후 Recovery 문서에 Safety 링크를 보강한다.

---

## 하드 안전 규칙 (문서·코드 공통)

다음을 **명시적으로 금지**한다.

1. **워치 HR / 떨림 / 모션만으로 저혈당 진단 금지.**  
   심박 회복 지연·모션 저하·사용자 증상 입력은 **이상 신호(anomaly)**일 뿐, 혈당 진단이 아니다.
2. **금지 UX:** `저혈당인가요? → 119` 직접 점프.
3. **올바른 프레이밍 (필수):**  
   - 허용: **「이상 신호가 있습니다. 안전을 확인하겠습니다.」**  
   - 금지: **「저혈당입니다」** (측정된 CGM/혈당 데이터 + 신중한 임상 주장 없이).
4. **상용 패턴은 UX 영감만.**  
   Apple 낙상 감지(움직임 대기 → 긴급), Samsung 낙상/SOS와 유사한 **대기·확인·카운트다운** 흐름을 참고한다. 의료 동등성·인증 주장이 아니다.
5. **CGM:** 실제 측정 혈당이 연동된 경우에만 **별도 glucose-aware 로직**. CGM 없이는 저혈당 진단·단정 문구 없음.

코드 스텁(`SafetyScore` 등)에도 동일 주석을 남긴다. 감지·SOS 단계는 저혈당 진단이 아니다.

## 단계적 에스컬레이션

### 1. Detect (감지)

다음을 **조합**해 이상 신호를 만든다 (단일 센서 단정 금지).

- 운동(걷기/뛰기) **종료**
- 비정상 **심박 회복**(연동 시; 미연동이면 이 축 생략)
- **모션 급감** / 낙상 후보
- Recovery에서 사용자가 고른 증상(떨림·어지러움 등)

출력은 진단명이 아니라 **이상 신호 플래그**다.

### 2. User confirm (사용자 확인)

진단명 없이 확인만 한다.

> 평소와 다른 신체 반응이 감지되었습니다. 괜찮으신가요?  
> `[괜찮아요]` `[도움이 필요해요]`

- `괜찮아요` → 주의 해제 또는 Recovery 안내로 복귀.
- `도움이 필요해요` → Danger / SOS 경로.

### 3. Recovery guidance (의식 있는 응답 시)

Safety가 Recovery 프로토콜을 **호출**할 수 있다 (소유권은 Recovery).

- 앉아서 쉬기, 물, (해당 시) 탄수화물 간식 등 생활 안내.
- 당뇨이거나 측정기/CGM이 있으면 **혈당 확인 권고**(advisory).  
  측정값 없이 「저혈당」이라 말하지 않는다.

### 4. Danger / SOS

다음이면 긴급 경로:

- 낙상 + **무모션**
- 확인 화면 **무응답**
- 사용자가 **「도움이 필요해요」**

카피 예시:

> 긴급 도움이 필요할 수 있습니다. 30초 후…  
> `[취소]` `[지금 SOS]` / `[119 연결]`

카운트다운 중 무응답 → SOS 에스컬레이션.

**이 문서 시점:** 실제 전화 다이얼·자동 119 발신은 **구현하지 않는다**(의도적 deferred). UI/도메인은 상태와 카피만 정의한다.

### 5. Silent timeout 예시 카피

무응답·무모션 타임아웃 경로 (진단명 없음):

> 이상 신호가 있습니다. 안전을 확인하겠습니다.  
> 응답이 없으면 긴급 도움을 요청할 수 있어요.  
> `[취소]` `[지금 SOS]`

카운트다운 종료 후에도 응답 없으면 SOS 상태로 전환한다.  
**금지:** 타임아웃만으로 「저혈당입니다」 또는 측정 없는 질병명 표시.

## Balmi Safety Score 상태머신

```
정상 → 주의 → 회복 필요 → 안전 확인 → 긴급
```

| 상태 | 의미 | 전형 트리거 |
|------|------|-------------|
| `정상` | 이상 신호 없음 | 기본 / 사용자 괜찮아요 |
| `주의` | 약한 이상 신호 | 운동 직후 HR·모션·증상 힌트 |
| `회복 필요` | Recovery 안내 권장 | 증상 입력 + 의식 응답 |
| `안전 확인` | 확인 UI·카운트다운 대기 | 강한 이상 / 낙상 후보 |
| `긴급` | SOS·보호자·119 안내 | 무응답 / 도움이 필요해요 / 무모션 |

전이 시 **진단 문자열을 붙이지 않는다.** Score는 운영·UX 상태이지 임상 스코어가 아니다.

도메인 스켈레톤: `lib/domain/engines/balmi_safety.dart` (`SafetyScoreLevel`).

## 미래 데이터 흐름

```
활동 → 생체반응 → 이상 신호 → 사용자 확인 → 회복 → 안전 → 긴급 대응
```

- **활동:** Balmi 세션(걷기/뛰기 강도·종료).
- **생체반응:** HR 회복, 모션, (옵션) CGM.
- **이상 신호:** 조합 룰 → Safety Score 상승.
- **사용자 확인:** 진단명 없는 확인 UI.
- **회복:** Recovery 모듈.
- **안전 / 긴급:** Safety 소유(보호자 알림·SOS).

---

## 컨텍스트 이점 (낙상만 대비)

Balmi는 운동 맥락을 안다.

`걷기/뛰기 강도 → 종료 → (지연) HR 회복 이상 → 떨림 입력 → 모션 급감`

낙상 전용 제품보다 **풍부한 전후 맥락**으로 이상 신호를 조합할 수 있다.  
그래도 **혈당 진단이 되지는 않는다** — 맥락은 에스컬레이션 품질용이다.

## 구현 경계 (이번 작업)

**한다**

- 문서화(에스컬레이션, 언어, 모듈 분리, Score, CGM 규칙, 로드맵).
- 순수 Dart `SafetyScoreLevel` 스켈레톤 + 「저혈당 진단 아님」 주석.
- SPEC / README / 개발노트 링크.

**하지 않는다**

- 119 자동 전화.
- HR/떨림/모션으로 가짜 혈당·저혈당 추론.
- `저혈당인가요? → 119` UX.
- CGM 없는 「저혈당입니다」 카피.

## 참고 (UX 영감만)

- Apple Watch Fall Detection: 낙상 후보 → 움직임/응답 대기 → 긴급 연락.
- Samsung 낙상 감지 / SOS: 확인·카운트다운·긴급 연락.

Balmi는 동일 **대기·확인·에스컬레이션** 패턴을 운동 맥락에 맞게 쓴다. 의료기기 동등 주장이 아니다.
